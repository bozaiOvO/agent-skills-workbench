---

## 一句话

**把内容创作从"凭感觉赌"变成可量化、可复盘、可进化的预测循环。**

你写一篇稿子 → 先打分 → 盲预测播放量（写完不许改）→ 发布 → T+3天拿真实数据对账 → 发现哪里判断偏了 → 修正你的评分公式 → 下一篇更准。

---

## 核心逻辑（5 阶段闭环）

```
打分(Score) → 盲预测(Blind Predict) → 发布(Publish) → 复盘(Retro) → 升级公式(Bump)
     ↑                                                                    │
     └──────────────────── 用新公式打下一稿 ─────────────────────────────┘
```

---

## 三条铁律（不可违反）

1. **盲预测不可篡改。** 预测写完就不能改——只能往「复盘」段追加。你没法"事后诸葛亮"自己骗自己。
2. **升级公式必须全量重打。** 改评分公式时，所有历史稿子都要用新公式重判一遍，必须比旧公式更准才放行，还要跨模型独立审核。
3. **评分规则是工作台不是博物馆。** 被数据推翻的观察删掉，被吸收的也删掉。只留当下最有用的。git history 才是档案。

## 你的内容项目长什么样（初始化后）

```
<你的内容项目>/
├── rubric_notes.md          ← 评分规则（核心资产，随你用越准）
├── WORKFLOW.md              ← 5 阶段流程说明
├── STATUS.md                ← 实时看板
├── .cheat-state.json        ← 状态文件
├── benchmark.md             ← 对标账号信息
├── audience.md              ← 受众画像（盲预测时禁止偷看）
├── scripts/                 ← 稿子放这里
│   └── 2026-06-09_001_选题.md
├── predictions/             ← 预测日志（写完即锁）
│   └── 2026-06-09_001_选题.md
├── videos/                  ← 拍摄后才建
│   └── 2026-06-09_001_选题/
│       ├── script.md
│       └── report.md
├── samples/                 ← 对标账号素材
├── candidates.md            ← 选题池
└── content.db               ← 可选 SQLite（规模化后启用）
```

## 为什么适合你（金波）

你要做的事和这个 skill 解决的问题完美匹配：

- 你有**对标账号**（程序员K哥、水球泡、杜老师讲IT…）→ `/cheat-learn-from` 导入
- 你需要**判断哪篇稿子更可能爆** → `/cheat-score` 打分
- 你想知道**自己的判断力是否在变准** → 盲预测 + 复盘对账
- 你在意**短视频、直播、私域**的复用 → 这套 system 的核心输出就是一个会进化的判断公式

这不是"AI 帮你写稿"的工具，而是"AI 帮你判断你的稿子哪里行哪里不行"的工具。稿子还是你写，判断力是它帮你练的。

## 首次使用

1. 进入你的内容项目目录
2. 对 Claude Code 说：`初始化 cheat-on-content`
3. 回答 5 个 yes/no 问题
4. **强烈建议立刻跑 `/cheat-learn-from` 导入对标账号**——至少 5-10 条样本，否则前 5 篇预测精度会很差

---

## 注意

- 这套 skill 的思想是**量化自我的内容创作版**，你得有耐心跑完至少 10 篇才能看到自己的判断力提升
- rubric 的质量决定了整个系统的上限——前几版 rubric 肯定不准，需要通过 bump 循环慢慢校准
- 内置的 rubric 是"观点类视频"的——如果你要做其他形态（直播切片、口播、访谈），需要自己改评分维度
- 盲预测是最关键也最难坚持的环节——人天生想"知道了结果再预测"，但这个系统强制你先预测再看结果
