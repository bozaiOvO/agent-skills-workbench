# 老宋IP短视频脚本创作

为老宋（IT职业培训招生官）写短视频脚本时的工作流程和注意事项。

---

## 核心原则

1. **深度是人的活，效率是AI的活**：AI不能凭空生成有深度的脚本——深度来自用户对话题的理解（聊天室讨论、自己想透的观点、真实经历）。正确分工：用户先把事情搞清楚，把核心思路写成大白话（哪怕几句话），AI再帮"说清楚"——润色结构、优化节奏、检查表达效率。流程反了（直接让AI从素材生成成品）出来的东西必然缺深度。
2. **内容深度 > 公式套用**：弹药库（04_爆款弹药库.md）的钩子公式和结构模板是包装工具，不是内容来源。对于有深度的话题（情感型、社会议题型），先找到真实洞察，再选合适的结构去装它。
3. **先回溯讨论再动笔**：如果之前用聊天室（dbs-chatroom）或其他方式讨论过这个话题，必须先回溯那些讨论内容（session_search、读文件），把讨论中产生的核心观点、用户自己说的话、专家的独到见解提炼出来，作为脚本的骨架。
4. **内容优先，业务跟随（7:2:1）**：7成纯内容、2成软植入、1成硬广。纯内容型脚本就把话题说透，不带任何业务。

## 写脚本前的检查清单

1. **有没有前置讨论？** → session_search 搜索话题关键词，看是否有聊天室讨论、用户观点、专家分析
2. **用户有没有明确的立意？** → 检查上下文中用户对这个话题说过的核心观点（这些比任何公式都重要）
3. **读核心文件**（按需，不必每次全读）：
   - 角色定义工作手册 — 铁律和禁止事项
   - 01_人设定位.md — 老宋是谁
   - 04_爆款弹药库.md — 钩子公式和结构（作为工具，不是内容源）
4. **确定脚本类型**：纯内容（7）/ 软植入（2）/ 硬广（1）

## 写脚本的顺序

**错误顺序**（公式驱动）：选钩子公式 → 套结构模板 → 填内容 → 标注元信息
**正确顺序**（内容驱动）：

1. 提炼核心洞察（从讨论/用户观点中来）
2. 确定情感落点（这条视频最后要让观众感受到什么）
3. 围绕洞察和落点写正文
4. 回头选一个最匹配的钩子开头（可以不严格对应某个公式编号）
5. 口语化打磨（念出来顺不顺）
6. 最后才标注元信息（公式来源、时长、标签）

## 写完后必须做内容诊断

脚本初稿完成后，用 dbs-content skill 做五维诊断（文字洁癖、封面/标题、表达效率、认知落差、AI辅助），再根据诊断结果改稿。不要跳过这一步直接交稿。

"寒门难出贵子"脚本的教训：初稿试图把聊天室四方观点全塞进75秒，结果五维诊断中"表达效率"和"认知落差"都亮红灯——贪多嚼不烂，每个点蜻蜓点水。

## 一条脚本只说一个点

75秒短视频只能承载一个核心观点。如果话题有多个好观点（比如来自聊天室多位专家），拆成多条独立脚本，每条打穿一个点。

错误做法：把"认知差""别怪父母""重新定义贵""自卑是燃料""需要有人拉一把"全塞进一条视频
正确做法：拆成独立脚本——一条只讲认知差，一条只讲别怪父母，各自说透

## 常见错误

- 话题有深度但脚本只有公式骨架，缺乏真实洞察
- 忽略之前聊天室/讨论中产生的好观点，从零开始套公式
- 元信息标注过于详细，像在交作业而不是写脚本
- 对深度话题强行融入弹药库的机械结构（如"痛点暴击→造梦三层→CTA"）
- 一条脚本塞多个观点，导致每个都浅尝辄止（75秒只够说透一件事）
- 跳过 dbs-content 诊断直接交稿，用户不满意才返工

## 脚本格式要求

- 两个钩子版本（铁律第10条）
- 口语化逐字稿
- 时长标注（短平快42秒内，标准60-90秒，故事型80-100秒）
- *斜体*标注需老宋填真实数据的部分
- 固定结尾语："我是老宋，带同学就业的老宋"
- 标签建议
