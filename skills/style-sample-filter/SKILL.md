# 文风样本筛选与反推规划 Skill

## 这个 skill 解决什么问题

用户手里经常有一整个文件夹的文案，但这些文案未必都属于同一种稳定写法。

直接拿全部文本去反推 prompt，常见后果有 3 个：

1. 把不同栏目、不同题材、不同阶段的写法混成一锅。
2. 把重复文本、错贴文本、标题党文本也当成有效样本。
3. 最后做出来的 prompt 很像这个人，但哪里都不准。

这个 skill 的工作不是立刻产出文风 prompt，而是先把「哪些文本值得拿来反推」这件事做干净。

你要做两步：

1. 从大量文本中筛选出适合反推一个或多个 prompt 的文本簇。
2. 拿筛选结果和用户确认；用户确认后，再调用「文风 DNA 深度解析」skill 去生成 `system prompt` 或模仿型 skill。

## 触发信号

出现以下情况时，直接使用本 skill：

- 用户给你一个文件夹，希望你判断哪些文本一致性高。
- 用户说想模仿某个人文风，但担心语料不稳定。
- 用户说「先别急着写 prompt，先帮我挑哪些样本适合」。
- 用户想判断一批文稿能否拆成多个文风 prompt。
- 用户明确要做「语料筛选」「语料清洗」「文风样本分组」「反推前预处理」。

## 输入形式

用户一般会给你以下一种或多种输入：

- 一个文件夹路径
- 多个文件路径
- 一个大文件，里面包含多篇文稿
- 用户口头说明的作者名、平台、题材线索

## 总原则

先筛选，再反推。不要跳步。

用户没确认之前，不要直接生成最终 `system prompt` 或最终 skill。

你要优先识别：

- 重复文本
- 错贴文本
- 题材混杂
- 栏目混杂
- 长短失衡
- 只有标题不同、正文相同
- 只有口号一致、结构并不一致

## Step 1：清洗语料

### 1.1 收集文本

- 如果是文件夹，优先读取所有 `.md`、`.txt`、`.docx` 可转文本内容。
- 如果文件过多，先建立清单，再决定抽样或全量去重。
- 如果文本来自 OCR 或转写，注意识别错字、断句混乱、口语噪音。

### 1.2 标准化文本

在比较一致性之前，先去掉这些不应影响判断的内容：

- 标题
- 链接
- 固定前后缀
- 发布时间
- 平台标签
- 重复出现的 CTA
- 无意义空白

如果这些部分本身属于文风结构的一部分，要在报告中单独说明，而不是直接忽略。

### 1.3 去重

必须做去重判断，至少检查这几类：

- 完全重复：正文完全相同
- 近重复：改了标题，正文基本不变
- 套壳重复：开头和结尾改了，中间主体一样
- 错贴：标题内容和正文主题明显不匹配

如果发现大量重复或错贴，要把这件事放到结论最前面说，因为这会直接影响后续 prompt 的可信度。

## Step 2：识别是否存在多个文风簇

不要预设「一个作者只有一种稳定文风」。

很多人其实是：

- 同一个口气，不同栏目
- 同一个价值观，不同表达模板
- 同一个人写 2 到 4 套固定栏目文风

你要从这些维度做分簇：

### 2.1 主题维度

- 两性 / 关系 / 阶层
- 商业 / 品牌 / 社会现象
- 财经 / 宏观 / 热点解读
- 个人感悟 / 价值判断 / 观点短打
- 带货 / 推荐 / 直播转化

### 2.2 结构维度

- 先抛问题，再拆本质，再下裁决
- 先讲案例，再抽象成规律
- 先给结论，再补论证
- 碎片观点短打
- 直播口播型推进

### 2.3 语气维度

- 裁判型
- 教练型
- 冷判断型
- 讲故事型
- 召唤行动型

### 2.4 词汇与修辞维度

- 是否高频使用商业隐喻
- 是否高频使用博弈、风控、资源、杠杆、阶层等词
- 是否偏短句推进
- 是否常用反问、设问、极端案例
- 是否常用「你以为」「本质上」「真正的问题是」这类结构

## Step 3：评估每个文本簇是否适合反推 prompt

每个候选文本簇都要给出判断，不要只给直觉。

至少从以下 6 个维度打分，每项 1 到 10 分：

1. 一致性：同一簇内部的表达骨架是否稳定
2. 独特性：是不是一眼就能和普通文案区分开
3. 完整性：样本是否足够长，能看出结构、词汇、节奏、价值观
4. 纯度：有没有混入明显不同栏目的写法
5. 可复制性：是否能被总结成可执行规则
6. 样本量：独立样本数量是否够支撑反推

### 适合做 prompt 的标准

优先选择满足这些条件的文本簇：

- 至少有 4 到 6 篇独立文本
- 不是同一篇正文反复套壳
- 句法、论证方式、价值判断有重复出现的稳定模式
- 有足够长的正文，而不是只有口号
- 题材虽不同，但底层表达模型相同

### 不适合做 prompt 的典型情况

- 大量重复，只是换标题
- 每篇都像不同的人在写
- 只有世界观一致，表达方法不一致
- 太短，只能学到口气，学不到结构
- 语料污染严重，错贴和搬运太多

## Step 4：输出筛选报告

报告必须先给结论，再给证据。

使用以下结构：

```markdown
# 文风语料筛选报告

## 一、结论
- 是否适合直接反推单一 prompt
- 是否更适合拆成多个 prompt
- 是否存在严重语料污染

## 二、语料健康度
- 总文件数
- 独立正文数
- 重复情况
- 错贴情况
- 题材混杂情况

## 三、候选文风簇
### 簇 A：名称
- 代表样本：
- 适合程度：高 / 中 / 低
- 判断：
- 风格骨架：
- 风险：

### 簇 B：名称
...

## 四、推荐反推方案
- 方案 1：只做 1 个 prompt
- 方案 2：拆成 2 个 prompt
- 方案 3：先补样本再做

## 五、建议用户确认
- 请用户明确要做哪个簇
- 请选择产出 system prompt 还是 skill
```

## Step 5：向用户发起确认

筛选完后，不要直接进入生成。

你要请用户确认两件事：

1. 要继续做哪一个文本簇，或哪几个文本簇。
2. 最终要产出 `system prompt`，还是产出「模仿这个人文风的 skill」。

如果用户没有明确指定，默认推荐最稳定、最纯、最完整的那一簇。

## Step 6：确认后调用下一个 skill

一旦用户确认，就调用「文风 DNA 深度解析」skill。

调用时，把这些信息一并传过去：

- 作者名或代称
- 已确认的样本文件列表
- 你对该文本簇的简短判断
- 用户希望输出 `system prompt` 还是 skill
- 如果用户希望做多个 prompt，说明每个簇的边界

## 交接模板

```markdown
请对以下已确认语料执行文风 DNA 深度解析，并产出最终结果。

作者 / 风格代称：[填写]
目标产物：[system prompt / 模仿型 skill]
已确认文本簇：[名称]
样本文件：
- [文件 1]
- [文件 2]
- [文件 3]

筛选阶段结论：
- [结论 1]
- [结论 2]
- [结论 3]
```

## 你要避免的错误

- 不去重，直接分析全部文本
- 把「作者本人主题稳定」误判成「文风稳定」
- 把短句口号也算作高质量样本
- 用户没确认就直接反推
- 明明应该拆成多个 prompt，却硬做成一个
- 把题材标签当成文风标签

## 判断优先级

当「题材一致」和「表达结构一致」冲突时，优先看表达结构。

当「篇数很多」和「独立正文很少」冲突时，优先看独立正文数。

当「口气像」和「论证方式像」冲突时，优先看论证方式。

因为最终要反推的是可执行的写作规则，不是表面腔调。
