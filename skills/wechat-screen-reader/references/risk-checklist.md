# 微信屏幕读取风险清单

## 必须确认

- 确认用户明确授权读取哪个联系人或群聊。
- 确认不读取数据库、不提取密钥、不扫描全量聊天。
- 截第一张全屏或窗口截图后，确认右侧聊天标题与目标一致。
- 若是私聊，确认左侧选中项和右侧标题一致；若是群聊，确认群名和人数/群标题一致。
- 保存一张会话确认截图，作为采集对象证据。

## 必须处理

- 文本气泡：OCR 后去重合并。
- 图片消息：不能只依赖缩略图 OCR，必须点开大图或从微信界面保存原图后再分析。
- 图片原图：优先从可见的微信消息通过「保存图片/另存为/保存到...」保存到任务目录，并记录页码、时间、前后文本和消息位置。
- 图片 OCR：先使用微信界面保存的原图；无法保存原图时，再使用清晰打开图/裁剪图；缩略图 OCR 只能当定位线索。
- 长跨度图片：不要把本地缓存扫描作为主方案。缓存图只能作为候选，必须匹配回可见聊天消息后才能写入正文。
- 视觉模式：如果用户明确不要 OCR 工具，必须改用模型视觉阅读截图；不要把视觉不清的文字硬凑成逐字稿。
- 长图：分段截图或连续缩略图逐张打开，分段之间保留重叠，直到上下文闭合。
- 低清识别：如果出现明显坏句、乱码、错字堆叠，不能直接进入正文；必须回看图片、重新分段/放大，或标注低可信。
- 文件消息：不能只记录文件名；在用户授权后通过微信 UI 打开/下载文件，复制到任务目录，按类型解析并总结内容。
- 引用消息：记录当前回复和被引用内容。
- 文件/链接/小程序/语音：至少标注存在；不能假装已读取。
- 撤回/系统消息：保留事实，但不要过度推断内容。

## 常见失败

- 截到 Codex 或别的窗口，而不是微信。
- 联系人名只出现在左侧列表，但右侧仍是别的会话。
- 滚动失焦，连续页面重复。
- Retina 坐标混淆：截图像素通常是屏幕点坐标的两倍。
- 图片查看器打开后未退出，后续截图仍是大图。
- OCR 把图片缩略图中的文字当作普通聊天文本，导致上下文顺序混乱。
- 扫描本地缓存得到大量无关图片，无法证明图片属于当前联系人、当前日期范围或当前消息位置。
- 从缓存中找到图片后没有匹配回微信界面的可见消息，却把它当成聊天原图写进报告。
- 低清图片 OCR 污染正文，例如把“强大自己”识别成坏句，导致分析建立在错误文本上。
- 视觉模式下误称“全文逐字识别完成”；截图视觉阅读只能保证清晰可见内容，模糊处必须标注。
- 文件只显示文件名但没有真正下载/打开，却在总结里误写成“文件内容显示”。
- 下载文件散落到系统下载目录，未复制进任务目录，导致后续无法审计来源。
- 临时截图、打开过的图片、下载文件留在工作区，造成二次隐私污染。

## 输出要求

- 最终报告文件名必须包含对象、聊天日期范围、生成时间戳：`微信_<对象>_<YYYY-MM-DD>～<YYYY-MM-DD>_聊天记录_<YYYYMMDD_HHMMSS>.md`。
- 最终报告正文顺序必须是：时间范围、生成时间、AI 总结、对话主线、全部正文内容、图片 OCR/文件附件、覆盖范围与未读取内容、清理说明。
- 时间范围必须写清楚从哪年哪月哪日几点几分到哪年哪月哪日几点几分；如果微信只显示“昨天/星期六”，要结合当前日期推断并标明“推断”。
- 同时输出原始 OCR、脱敏 OCR、最终报告、漏洞/未覆盖清单。
- 明确哪些内容来自图片 OCR。
- 图片附件要列出保存方式：微信界面保存原图、打开大图截图、或缓存候选；缓存候选必须标注是否已匹配上下文。
- 明确哪些内容来自文件解析，并列出每个文件的文件名、类型、处理状态和摘要。
- 明确哪些内容没有读取到，例如语音、链接内容、未打开图片、未下载文件、无法解析文件。
- 提醒原始截图目录敏感；如果用户要求不留痕，最终删除截图、图片切片、下载文件和 OCR JSON，只保留最终报告。
